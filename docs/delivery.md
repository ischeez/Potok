Первичная проверка — 22 октября 2026 года; проверка релиза и публикация на VPS — 3 ноября 2026 года. Репозиторий создан отдельно, ветка — `feat/kanban-board`.

## Проверки

- Чистая установка через `npm ci` по закоммиченному lockfile.
- `npm run check`: ESLint, TypeScript, 8 API unit-тестов, 4 frontend unit-теста, сборка обоих приложений. Повторно успешно выполнено 3 ноября.
- `npm run test:integration`: 3 дополнительных сценария с настоящим PostgreSQL в `potok_test`; вместе с unit-тестами API проходят 11 тестов. Повторно успешно выполнено 3 ноября.
- `npm run test:e2e`: 15 браузерных проверок проходят. Один desktop drag-сценарий намеренно пропускается в мобильном проекте; перенос через меню проверяется на телефоне в полном CRUD-сценарии.
- Проверены ширины 320, 390, 768, 1024, 1440 и 1920 px.
- Миграция и seed запускаются повторно без повторного создания схемы и демонстрационных задач.
- Визуально просмотрены скриншоты компьютера и телефона.
- Отдельно запущены собранный NestJS и `vite preview`: задача создана через интерфейс и прочитана из PostgreSQL, ошибок выполнения в браузере нет.

Локальное окружение: macOS, Node.js 26, Chromium и PostgreSQL 17 в Docker. Минимальная заявленная версия Node — 22.12; workflow GitHub Actions настроен на Node 22. Сам workflow пока не выполнялся на GitHub, поскольку репозиторий ещё не опубликован.

## Что изменилось после проверки

Интеграционные тесты поймали важную деталь DTO: TypeScript создавал собственные поля со значением `undefined`, из-за чего частичный `PATCH` мог записывать лишние значения. Теперь обновляются только реально переданные поля; пустое обновление возвращает `400`.

Браузерный сценарий обнаружил отправку формы при переходе из просмотра к редактированию. У кнопок разные ключи и явные типы, переход отменяет стандартное действие клика. Редактирование, сохранение и перезагрузка проходят в обоих браузерных проектах.

После проверки мобильного скриншота исправлены ширина прогресса и отображение ручки перетаскивания на сенсорном экране. Импорты иконок сделаны адресными: сборщик обрабатывает около тысячи модулей вместо более чем одиннадцати тысяч.

Холодный запуск тестов выявил гонку готовности: Vite уже отвечал, пока NestJS ещё компилировался. Playwright теперь ждёт отдельно интерфейс и успешный `/api/health`, прежде чем открывать доску.

## Ограничения

Это одна открытая общая доска. В production интерфейс, файлы и API доступны без логина и пароля; любой посетитель может изменять задачи. Пользовательских аккаунтов внутри приложения нет. Нет живой синхронизации между вкладками, пагинации и офлайн-режима. При одновременном редактировании применяется последняя запись. Внутри колонки нет ручного порядка карточек. Отдельные удалённые задачи не восстанавливаются через интерфейс.

Для сервиса с несколькими пользователями потребуются собственная авторизация и привязка задач к владельцу. Подробности текущего развёртывания — в [инструкции VPS](deployment.md).

## Проверка опубликованной версии

На `https://korotkov.click` настроены HTTPS и Cloudflare Full (strict). PostgreSQL и API не публикуют свои порты наружу. Контейнеры автоматически запускаются после перезагрузки сервера, логи ограничены по размеру.

При первоначальной публикации на сервере `deploy/verify-release.py` проверил закрытый доступ, TLS, заголовки, файлы интерфейса, создание и изменение задачи, завершение, сохранность после перезапуска API и удаление. Отдельно проверено восстановление gzip-дампа в временную базу. Проверочные данные после проверки удалены. По просьбе владельца вход по паролю затем отключён; текущая конфигурация и verifier используют открытый доступ.

Ежедневный systemd timer резервного копирования включён и проверен ручным запуском. Архивы хранятся семь дней на самом VPS; внешнее хранилище резервных копий пока не подключено. Пароли отсутствуют в репозитории.

## AI и время

AI участвовал в структуре проекта, визуальном оформлении, API, миграциях, тестах и документации. Проверка опиралась на реальные команды, базу и браузерные сценарии. Скриншоты сгенерированы из работающего приложения.

Первоначальная сборка заняла около 30 минут активной работы с AI. Позже отдельно дорабатывались оформление и production-запуск. Суммарное время этих доработок не замерялось, поэтому оценка первоначальной сборки не является временем всего проекта.
